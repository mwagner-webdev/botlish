# Mutants of exhaustive matches (audit/exhaustive-match/tools/mutate.tcl;
# PORTABILITY-EXHAUSTIVE-MATCH-MILESTONE-1.md, section 14): each a
# deliberate bug in one of the milestone's invariants -- exhaustiveness,
# duplicate and nominal coverage, selection by identity only, a payload
# taken only under its own selection, the payload's declared type, one
# evaluation of the scrutinee, ownership of an affine scrutinee, the
# readers' re-checks, the backends' selection.
#
#   @@ NAME DESCRIPTION
#   ## FILE
#   <<<<
#   text to replace (must occur exactly once in FILE)
#   ====
#   replacement
#   >>>>
#
# A mutant may have several edits. A mutant editing native/src/ is a native
# mutant: mutate.tcl rebuilds the native backend for it. Lines starting with
# # outside an edit are comments.
#
# Not here, with the reason:
#
#   * a binding escaping its arm: an arm's bindings are bound in its `if`
#     branch's scope, which the ordinary resolution of branch scopes closes
#     (em-payload-binding-diagnostics's UNBOUND); there is no match-specific
#     code to mutate.
#   * an arm left out of the result's join, an arm's return or failure
#     turned into a value: the arms are an `if` chain, joined and completed
#     by the ordinary `if` rules (hir/types.tcl's If, the completion walk),
#     whose own harnesses mutate them.
#   * a native payload left unrooted while it is extracted: rt_enum_payload
#     reads one field and allocates nothing, so no collection can run while
#     the payload is unrooted (em-gc-stress and the fuzzer's -gc-stress run
#     check what the arm then allocates).
#   * a semantic instance's case facts surviving its rollback: a match
#     writes no HIR field while it is typed (MatchSyntax writes the
#     constants at resolution; the selections' types are pure functions of
#     them), so there is nothing for a walk to leave behind (em-rollback-
#     audit runs the audit).
