# Mutants of Botlish-owned threads and the cross-thread transport
# (audit/threads/tools/mutate.tcl; BOTLISH-OWNED-THREADS-AND-CROSS-THREAD-
# ACTORS-MILESTONE-1.md, "Mutation testing"): the runtime's thread registry
# and transport (native/src/runtime/thread.rs), the Linux driver's
# per-loop state (packages/event_loop_linux/native/event_loop_linux.c), the
# compiler's thread-entry rules (hir/threads.tcl, hir/contexts.tcl) and the
# library (stdlib/thread.bot, stdlib/actor/remote.bot, core/transfer.tcl).
#
#   @@ NAME DESCRIPTION
#   %% HOST ...        (optional) the host targets the mutant applies to
#   !! DETECTOR ...    the detectors meant to kill it (one at least), each
#                      KIND:NAME -- rust-lib:TEST (a Rust test whose path
#                      contains TEST), FILE:TEST (tcltest TEST of
#                      tests/FILE, a -match pattern)
#   ## FILE
#   <<<<
#   text to replace (must occur exactly once in FILE)
#   ====
#   replacement
#   >>>>
#
# A mutant is KILLED only when one of its own detectors fails (or does not
# complete: a mutant that leaves a call or a loop waiting forever is killed
# by the run's timeout). Lines starting with # outside an edit are comments.
#
# Not here, with the reason (the brief's list of defects, section 21, by
# layer; each one's defense):
#   * "Initialize a VM on the parent thread and move it to the worker",
#     "Destroy a VM before its thread finishes", "Free a transport buffer
#     before decoding", "Enqueue a sender heap pointer": no small edit
#     expresses them -- a Vm is not Send (its thread makes it: thread.rs's
#     run_entry), and a message is a Vec<u8> the transport owns, copied
#     from the sender's byte storage and handed to the receiver's
#     constructors (rt_take_bytes); each would need a rewrite the compiler
#     refuses.
#   * "Share a context area between workers", "Read program metadata from
#     the wrong VM": the per-thread runtime harness's ctx-* and program-*
#     mutants (audit/per-thread-runtime), whose detectors run several Vms.
#   * "Leak a guard slot after termination": a record is released when its
#     guard drops and again when its thread ends (records.rs's thread-exit
#     release), so no single edit of the thread runtime leaks one.
#   * "Drop a wakeup between empty-check and wait": the event loop's
#     c-reset-without-recheck and c-wake-not-owed (audit/event-loop), and
#     the port's own reset-then-recheck (port_notifications_are_never_lost,
#     doorbell-silent below).
#   * "Route a response to the wrong worker", "Complete a cancelled request
#     with a later response": a response is queued on the reply endpoint
#     its call recorded (Transport::complete), the call matched by slot,
#     generation and key -- answered-twice and call-generation-unchecked
#     below. There is no explicit cancellation operation: a call is
#     cancelled when its caller's reply route closes, which calls_complete_once
#     covers.
#   * "Block the worker's whole OS thread while awaiting a broker reply",
#     "Let an owner waiting for a worker monopolize the service actor":
#     properties of the composition (call suspends an actor; the owner's
#     supervise task waits with wait_end), not of one line of code.
#   * "Join returns before the OS thread exited" (wait_ended without its
#     JoinHandle join): the window is a few microseconds after the entry's
#     end, so th-abi-loops sees it only sometimes; a detector that kills it
#     every time would need a hook in the runtime.
#   * "Share a heap object between VMs": no code path hands one VM's value
#     to another -- every crossing is transfer bytes (std::transfer's own
#     mutants, audit/value-transfer, kill a codec that keeps a reference).
