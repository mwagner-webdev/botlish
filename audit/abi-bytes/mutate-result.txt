What each mutant is (see the header of tools/mutate.tcl):

  length-off-by-one        the native length accessor returns one too many
  nul-as-terminator        native creation stops at the first zero byte
  payload-offset-by-one    the address bridge returns the payload address + 1
  byte-masked-to-7-bits    native creation stores byte & 0x7f
  count-truncated          write's count register carries length mod 2^16 (the
                           same bug as truncating a Usize count to U32, which
                           only a 4 GiB payload could expose)
  no-keepalive             the lowering never emits the keepalive after a syscall
  address-in-rdx           the address and count registers swapped in the wrapper
  libc-write               the syscall boundary calls libc write(2) for rax = 1
                           instead of executing the syscall instruction: the
                           bytes written on success are identical; killed by
                           the raw-negative-result tests (libc returns -1 and
                           sets errno where the instruction returns -EBADF /
                           -EAGAIN) and by the strace-based test (the write's
                           call stack runs through libc); the strace test is
                           skipped where ptrace is unavailable, the errno
                           tests are not
  write-twice              the wrapper performs the syscall twice
  equality-by-identity     two storages are equal iff the same object (native)
  hash-ignores-length      the native hash omits the byte count
  static-constant-ascii    a static byte constant encoded as ASCII, not UTF-8

Notes:

* hash-ignores-length is killed by exactly one test -- the one that compares
  the native hash VALUE against the documented hash (the equality/hash
  consistency tests cannot see it: equal values still hash equal).
* count-truncated used to be a vacuous kill: the first version of the mutant
  did not compile, so every test "failed".  The tool now refuses a Tcl-side
  mutant whose example does not compile, and the mutant became a `trunc16`
  helper that compiles and is killed by the large-write, short-write and pipe
  tests.  (A U32-count mutant itself is unobservable below 4 GiB.)
* The tool's earlier version ran several mutants from one working directory
  while tcltest keeps its scratch directories there, so concurrent runs shared
  and deleted each other's files; each mutant now runs inside its own copy.
  A Rust mutant is not probed for compile errors (the crate building is
  enough, and a write that is one byte long or one byte off legitimately
  breaks the in-process runner's own output).
