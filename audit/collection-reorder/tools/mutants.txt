# Mutants of proven collection reordering (PROVEN-COLLECTION-REORDERING.md,
# "Mutation testing"), in audit/mutable-map/tools/mutants.txt's format, run
# by audit/collection-reorder/tools/mutate.tcl (the collections' harness,
# audit/mutable-map/tools/mutate.tcl, with this file, the reorder tests
# first, the collection fuzzer and the proof fuzzer).
#
#   @@ NAME DESCRIPTION
#   %% tests FILE ...      (optional) test files run first for this mutant
#   ## FILE
#   <<<<                   (or `<<<< all`: replace every occurrence, at
#   text to replace         least one; plain `<<<<` must occur exactly once)
#   ====
#   replacement
#   >>>>
#
# Three families: the semantics of the reorder (std::ordered_table,
# std::mutable_map, std::mutable_set), the soundness of the relational
# proof (hir/relations.tcl, the recovery rule in hir/recovery.tcl), and the
# value semantics a reorder relies on (copies, observers, the loop
# snapshot: compiler and runtime mutants of the seams the collections
# already use).
#
# Brief mutants with no non-equivalent mutant here (the report explains
# each):
#
#   * "reorder replaces stored key with candidate's equal key": two equal
#     Hashable keys are indistinguishable (audit/mutable-map/tools/
#     mutants.txt's header: the same for replacement); permute moves the
#     table's own keys and never reads the order's.
#   * "same length implies SameMembers", "subset implies SameMembers": the
#     static proof reads no length or membership fact (a relation is
#     minted only by a contract), so the mutants of that family are the
#     validator's: validate-length-only, validate-subset-only; and the
#     proof that admits whatever is well typed: any-order-admitted.
#   * "failed validation changes an input": validate_order takes both
#     values as ordinary parameters (copies): no code in it can change the
#     caller's collection or candidate.
#   * "relation lost after read-only operation" by a read's own contract:
#     reads have none; reads-lose-relation is the analysis's version.
#   * "the order's dead entries ranked": an order's dead entry (h = -1,
#     m.order() after removals shares the map's) is skipped by the
#     arrangement's `h < 0` test, and without it by the probe, which never
#     matches -1 (the index holds live positions only: removal is a
#     backward shift), whose -1 the totality's `p < 0` then skips. The
#     test is a shortcut, its removal equivalent.
#   * a handler entered without the handled call's changes: the handled
#     call's own completion carries them into every join, so in a program
#     the walk can see, the entry's kills never decide (the report).

# ---------------------------------------------------------------------------
