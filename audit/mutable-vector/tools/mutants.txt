# Mutants of MutableVector[T] (audit/mutable-vector/tools/mutate.tcl;
# MUTABLE-VECTOR.md): the mutants the milestone brief names (item 88), each a
# deliberate bug in the affinity query (hir/types.tcl), the ownership
# analysis and release elaboration (hir/affine.tcl), the place and
# copy-on-write elaboration (hir/mutvec.tcl), the Tcl runtime
# (core/mutvec.tcl, core/affine.tcl, core/evaluator.tcl,
# compiler/compiler.tcl) or the native runtime (native/src/runtime/mutvec.rs,
# affine.rs, heap.rs).
#
#   @@ NAME DESCRIPTION
#   ## FILE
#   <<<<
#   text to replace (must occur exactly once in FILE)
#   ====
#   replacement
#   >>>>
#
# A mutant may have several edits. A mutant editing native/src/ or the
# native crate's manifest is a native mutant: mutate.tcl rebuilds the native
# backend for it. Lines starting with # outside an edit are comments.
#
# Brief mutants with no non-equivalent mutant in this representation:
#
#   * "vector drop walks capacity rather than length": neither runtime has a
#     slot beyond the length to walk. A Tcl list has no capacity; a native
#     VecDeque's spare capacity holds no Value (`iter()`/`get(i)` stop at the
#     length, and reading uninitialized slots is not expressible in safe
#     Rust). `mutvec.rs`'s drop takes the live elements out first.
#   * "old backing remains traced as a second affine owner": an affine
#     vector's backing is never shared (a copy is a move; `owned` panics on a
#     shared one), and growth reallocates inside the VecDeque: there is no old
#     backing. Tracing is marking, never ownership -- releases happen only at
#     the static drops -- so a backing traced twice is the same program.
#     trace-omits-elements is the tracing mutant that is not equivalent.
#   * the native twin of "clear releases an element twice" and "vector drop
#     order reversed": a native coroutine release is idempotent and native
#     runs record no release order, so both are observably the same program
#     there; the Tcl runtime's (release-call probe, release trace) are the
#     mutants.
#
# Growth mutants on the Tcl runtime: a Tcl list has no capacity of its own,
# so they act where a doubling vector of capacity 4 grows (a length that is
# a power of two, at least 4); the native one acts where the VecDeque's
# capacity changes.
