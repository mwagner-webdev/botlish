# Mutants of general affinity and callable abstraction
# (audit/affine/tools/mutate.tcl; AFFINE-VALUES.md): the mutants the
# milestone brief names (item 72), each a deliberate bug in the affinity
# query (hir/types.tcl, hir/structs.tcl; its applications of parameterized
# structs: AFFINE-PARAMETERIZED-APPLICATIONS-CORRECTNESS-MILESTONE-1.md, item
# 13), the ownership analysis and release
# elaboration (hir/affine.tcl), the callable contract and generic
# specialization (hir/types.tcl, hir/semantic.tcl, hir/traits.tcl,
# hir/coroutines.tcl) or the drop runtimes (core/affine.tcl,
# native/src/runtime/affine.rs, native/lower.tcl).
#
#   @@ NAME DESCRIPTION
#   ## FILE
#   <<<<
#   text to replace (must occur exactly once in FILE)
#   ====
#   replacement
#   >>>>
#
# A mutant may have several edits. A mutant editing native/src/ or the
# native crate's manifest is a native mutant: mutate.tcl rebuilds the native
# backend for it (native/lower.tcl is Tcl, read by every native test run, and
# needs no rebuild). Lines starting with # outside an edit are comments.
#
# Not a mutant: "dropping an affine List releases an element twice" on the
# native backend. A coroutine release is idempotent by design (a released
# handle's second release returns at once, rt_co_release), so a native drop
# that visits an element twice is observably the same program; the Tcl
# runtime's twice-visiting drop is the mutant (list-drop-twice), caught by
# the release-call probe (core::coroutines::releaseCalls) that counts every
# release call, not every first release: tests/affine-applications.test's
# aa-release-calls-once, deterministically (the fuzzer's release check kills
# it only when a seed happens to drop a List of handles).
